# Code Review

Use for inline review comments and review summaries.

- Keep inline comments very short, blunt, and minimal.
- Lead with the concern or preferred form. Add one concrete consequence when the reason is not obvious.
- Ask a direct question when the trade-off is genuinely open; state the fix when it is not.
- Show the preferred form directly when that is clearer than explaining it.
- Admit missed context or correct an earlier comment immediately, without defensive explanation.
- A small 👍, 👏, 🤔, or 😅 can soften uncertainty, correction, or approval without weakening the point.
- Keep approval tiny. Spend words on unresolved risk.
